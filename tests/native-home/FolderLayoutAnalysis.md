# Open-folder layout: launcher 8.01.02.7722

The supplied ARM64 Flutter AOT image contains these symbols and instruction chains:

- `FolderGridViewGetxController.calItemSpacing` (RVA `0x8ef908`, size `0x12c`) stores the horizontal spacing at tagged receiver offset `0x43` and the vertical spacing at `0x3b`.
- The two normal vertical-spacing branches use `FMOV D0, #12` then `STUR D0, [X0, #0x3b]` (at `0x8ef9dc`), and `FMOV D0, #8` then `STUR D0, [X1, #0x3b]` (at `0x8efa00`). The stock default therefore depends on launcher mode.
- `FolderGridViewGetxController.calculateGridViewItemPosition` loads that `0x3b` field at `0xef8028`, adds the value to `folderCellHeight`, and multiplies the resulting pitch by the row index. This proves the field is the gap between rows, rather than the icon/cell height.
- The packaged `libhyperpatch.so` already implements feature 27: `LocateTrialFeatures` looks up `calItemSpacing` and requires two matching FMOV-to-STUR chains at `0x3b`. Its ARM64 shape predicate preserves the destination register; no hardcoded launcher RVA is introduced by the settings UI.
- Native V18 `ParseConfigBlob` reads the old absolute-spacing word at payload base + 60 into Config + `0x58`, and clamps it to 31. Feature 27 is now always omitted and its value stays zero. An optional 16-byte `FGRS` extension (version 2, explicit enable flag, signed absolute value) follows the V18 payload, preserving column/recents compatibility. Old v1 relative blobs cannot enable the new feature.
- `libhyperchanger_folder.so` uses the HyperOS native loader entry independently of Dock development. It finds `calItemSpacing` by a guarded instruction layout inside the mapped `libapp.so`, including APK-embedded images. It replaces the first instruction of both verified return epilogues with an atomic ARM64 branch through a permanent nearby island. The replacement reads the receiver spilled at `FP-8`, assigns the absolute gap at `0x3b`, preserves the full Q0 register and NZCV, and executes the original Dart epilogue. No C call or runtime safepoint runs on the Dart thread.
- This supports every integer from -20 through 80 exactly, including the disabled-spacing and elderly-mode branches. Enabled zero is a zero gap. The new enable preference defaults to false; disabled means stock gap and no spacing branch patches. The absolute value is remembered across toggles. The old relative preference is ignored.
- A forked launcher can still have `/system_ext/bin/hyos_spawner` as its executable. The entry now distinguishes the pre-fork parent from a launcher child using PID and UID, rather than excluding every process with that executable. No monitoring thread is started in the root pre-fork parent.
- The observer reads the atomic config file every 500 ms and checks patched instruction ownership against backing file/device/inode/offset. If the runtime discards a patched COW page, only the verified original epilogue instruction is restored to our branch. Disabling first publishes a sentinel (so any in-flight branch performs no heap write), then restores the original instructions. Unknown instructions are left untouched. Unsupported/ambiguous layouts do not get patched. A changed value is used on the next stock spacing calculation; already laid-out folders may need reopening.
- Folder columns use existing feature 16. Its native decoder supports 1..16; the requested UI restricts custom values to 1..15. The preset selection and last custom value are stored separately.

These findings are static analysis. Device verification requires a manual installation and user-triggered launcher reload; agent device operations remain restricted to log reads.

Verification: 9,696 Kotlin-to-native configuration combinations (columns, recents mode, every spacing value, enabled/disabled); unique instruction-layout match in the supplied AOT image; 808 executions of the linked ARM64 epilogue in Unicorn covering absolute values, disabled sentinel, zero, stack/frame restoration, Q0/Q1 preservation, horizontal gap, and NZCV. Live device log reads did not retain this library's entry or installation messages; on-device success is not confirmed.
